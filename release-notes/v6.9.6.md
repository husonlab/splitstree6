# SplitsTree 6.9.6

## New features

- networks now say what kind of thing they are: a **DistanceNetwork** (edge weights are lengths realizing
  a metric), a HaplotypeNetwork (weights are numbers of mutations), or a set of points. The viewer uses
  this to decide what to report, so a network read from a file shows its total length where it used to
  show nothing at all, and the edge filters now decline a PCoA point cloud instead of pulling it apart.
  An unrecognised type in a file is read as "Other" with a warning rather than refusing the file --
  note, though, that a file written with `TYPE DistanceNetwork;` will not open in version 6.9.5 or earlier
- new **Simplify Filter** for networks: say what you want -- a distortion or an excess you are willing to
  tolerate, a number of edges, a number of independent cycles, or just "the knee" -- instead of hunting for
  a stretch percentage. It works out one nested sequence of edge removals, cheapest first, so every goal is
  a point on the same sequence, and prints the whole trade-off table (cycles, edges, length, distortion,
  excess) so the choice can be made once and informed. By default it reports and changes nothing. Haplotype
  networks are measured in excess mutations rather than distortion, and a target that costs much more than
  the knee says so
- added one significant digit to fit representation
- added FMMM layout algorithm to network layout
- Hamming distance has two new options, "Match ambiguity codes" (on by default) and "Match gap to gap" (off by
  default), replacing the old "Handle ambiguous states" option
- LogDet was undefined for every pair of taxa on protein alignments, and on any nucleotide alignment read from
  PHYLIP or FASTA that contains ambiguity codes; it now works

## Changed results

This release corrects a number of long-standing errors in how sequences are handled, so distances computed on
nucleotide and protein alignments may differ from those reported by earlier versions.

- Hamming distance (and P distance) miscounted differences wherever ambiguity codes were present; unnormalized
  counts were inflated by up to 35% on such data

- estimated base frequencies were computed over the wrong alphabet, and left out the first taxon, the first
  site and the last site of every alignment
- the Phi test now treats an ambiguity code as missing rather than as a state of its own

## Bug fixes

- a distance-based network was drawn with one hatch mark per unit of edge length -- 4,272 of them on a
  20-taxon example, up to 238 on a single edge. Hatch marks count mutations, so they are now drawn only on
  a haplotype network, and a distance network defaults to showing nothing on its edges (its lengths are
  already drawn to scale; "Weights" or "Counts" still label them on request)
- network layouts placed terminal taxon nodes so that their pendant edges crossed other edges: the
  force-directed layout was asked to keep the positions it was given, but was given none, so every node
  started on the origin and the drawing was untangled by numerical jitter alone. Both network layouts are
  now started from a crossing-free drawing of a spanning tree, and several candidate drawings are scored
  so that the most readable one is kept; on the rhabdovirus examples pendant-edge crossings fall by around
  90%, and large networks lay out faster than before
- the network viewer reported no total length or excess for a haplotype network that had been put through
  the Stretch Filter: it looked for the alignment exactly two steps back in the workflow, and a filtered
  network is further away than that; it now looks back through any number of network-to-network filters
- the Stretch Filter lost the mutations of every edge it made by dissolving a redundant node, so a filtered
  haplotype network drew far fewer mutations than its own edge lengths called for - 190 of 616 went missing
  on the PAegRV example. Such an edge now carries the mutations of the whole path it replaces, and the
  total length reported counts the mutations drawn
- Fixed bug that prevented version number from appearing correctly in the About screen
- Hamming distance now handles gaps, missing characters and ambiguity codes as documented: a site is compared
  only where both sequences have an observed character, and 'N' (protein 'X') counts as missing
- RNA alignments containing ambiguity codes could not be read or analysed at all, the codes being written in
  terms of DNA and never translated; RNA alignments using codes other than R and Y were not even recognised
- several divisions by zero could put NaN into a distance matrix; one of them left LogDet looping indefinitely
  rather than returning
- gene sharing distance produced undefined entries (35 of them on the dolphins_binary example)
- ambiguity codes were counted as states, which is what made the frequency matrix singular for the algorithms
  above; protein's B, Z, X and the stop codon are now treated as missing

## Known issues

- LogDet requires every state to be observed within a pair of sequences, so it stays undefined for most pairs
  of a strongly skewed protein alignment
