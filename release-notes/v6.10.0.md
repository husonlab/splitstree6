# SplitsTree 6.10.0

## New features

- **RazorNet** and **RazorHaploNet**, two new algorithms by Momoko Hayamizu and Daniel Huson (paper in
  preparation), compute a network that displays the input distances exactly, with as little total edge length as
  the search finds. RazorNet takes a distance matrix; RazorHaploNet takes an alignment, computes the Hamming
  distances between its sequences, builds the network on them and labels the edges with the mutations that they
  stand for, which gives a haplotype network. A network that is too complex to read can be simplified afterwards
  with the Shave Filter. The two are listed as Razor Net and Razor Haplo Net wherever algorithms are added to a
  distances or characters node (the + button of the workflow side bar, the context menu of the node), and they
  run in workflows on the command line
- **TCS** and **TCS Haplotype Network** compute a haplotype network by statistical parsimony (Templeton,
  Crandall and Sing 1992), from distances that count mutations and from an alignment, following the
  implementation in PopART (Leigh and Bryant 2015)
- **File → Import → Haplotype Data** offers RazorNet as a method, next to Median Joining and Min Spanning Network; it
  applies RazorHaploNet to the grouped haplotypes
- these algorithms come from the `razornet-algorithms` library of the RazorNet project,
  <https://github.com/husonlab/razor-net>, which the installers and the command-line tools now include. The
  RazorNet program, a stand-alone program for the same algorithms, has its own installers there

## Bug fixes

- **K2P distance**: the exact Kimura two-parameter distance applied the corrections for invariable sites and for
  gamma-distributed rates to the wrong quantities, the reciprocals of 1 - 2P - Q and 1 - 2Q rather than to those
  values themselves. With a proportion of invariable sites of zero and no gamma rates, the default, the result
  was correct; with either option set it was not, and the gamma-corrected distance did not agree with the
  formula of Jin and Nei (1990). The corrections are now applied as they are for the Jukes-Cantor and F81
  distances. Maximum-likelihood K2P distances were never affected

- **Add-algorithm menu in the workflow side bar**: the menu of the + button kept the items of the data node that
  was selected first, when the selection moved on to another data node. It now always lists the algorithms for
  the node that is selected
- **Workflow side bar, + button**: the button was disabled for view nodes such as SplitNetwork and TreeView, so
  that Show Text, Export and As Network could only be reached through the context menu. Its menu now starts with
  the items that apply to the selected node (Show Text..., Export... and, for a split network or tree view,
  As Network...), followed by the algorithms that can be added
- **World map**: opening a document with a world map view could throw a NullPointerException while the view was
  not yet showing
- **Tanglegram**: the selection rectangle can be opened anywhere in the view and may span both trees

## Touch screens

- **Box selection**: after a long press and drag, the selection rectangle stayed open and nothing was selected.
  The rectangle now follows the finger also while it passes over edges and labels, the view no longer pans
  under it, and lifting the finger completes the selection
- **Pinch to zoom**: in the tree view and the DensiTree view, a pinch with the fingers side by side zooms
  horizontally and a pinch with one finger above the other zooms vertically; a diagonal pinch, and any pinch on a
  radial or circular diagram, zooms both. The DensiTree view used to zoom horizontally only
- **Scroll bars**: in the split network view, the scroll bars stayed visible after zooming or after a box
  selection. They now fade again as in the other views

## Changed results

- K2P distances computed with the **Prop Invariable Sites** or **Gamma** option set differ from those reported by
  earlier versions; for example, for transition and transversion proportions of 0.1 each, a proportion of
  invariable sites of 0.2 now gives 0.307 rather than 0.282, and a gamma shape of 1 gives 0.277 rather than 0.200.
  Distances computed with the default options are unchanged
