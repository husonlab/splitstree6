# SplitsTree 6.11.0

This release corrects a number of errors in the methods that compute distances from characters and in some of
the methods that take distances as input. Several of them change results that are obtained with the default
options; these are listed under Changed results.

## New

- **Remember Settings**: the tab of each method has a button with three dots before the Run button. Remember
  Settings stores the current option values as your own defaults for that method; a step of that kind that you
  add later starts with them. Use Remembered Settings applies them to the current step, Factory Settings sets
  all options back to the built-in defaults, and Forget Remembered Settings discards what was stored. Remembered
  settings are not applied when a file is opened or by the command-line tools

- **Razor Net and Razor Haplo Net**: when one of these methods is added, its network is passed through the
  Shave filter and the result of that is shown

## Bug fixes

- **Protein ML Distance**: for alignments read from FASTA, phylip, Clustal, MSF or Stockholm files, the amino
  acids were passed to the substitution model in the wrong order, so that all distances were incorrect. Those
  readers list the amino acids that occur in the alignment in alphabetical order, whereas the models (JTT, WAG,
  Dayhoff and the others) use the order A R N D C Q E G H I L K M F P S T W Y V. The observed frequencies are now
  handed to the model in the model's order, whatever the order of the symbols. Alignments read from Nexus files
  with `datatype=protein` were not affected
- **Files written by earlier versions**: when a file is opened that was written by a version before 6.11.0 and
  that contains Protein ML distances for an alignment with the amino acids in another order, a warning explains
  that the distances, and all results computed from them, are shown as stored and are not correct. Running
  Protein ML Distance again updates them
- **GTR distance**: the exact distance used base frequencies of ¼ each, which could not be changed, rather than
  those of the two sequences being compared. For sequences of unequal base composition this gave distances
  that were far too large, and a distance greater than zero between two identical sequences. The base
  frequencies of the two sequences are now used, as the formula of Rodríguez et al. (1990) requires. The rate
  matrix and the Base Frequencies option, which is now available for this method, apply to maximum-likelihood
  distances only
- **Jaccard distance**: the method computed the Dice distance, 1 − 2a/(2a+b+c), rather than the Jaccard
  distance, 1 − a/(a+b+c), where a is the number of characters present in both taxa and b and c are the numbers
  present in only one of them
- **Gamma-distributed rates with maximum-likelihood distances**: the transition probabilities for
  gamma-distributed rates were computed with an incorrect formula. This affected Protein ML Distance with the
  Gamma option set, and the K2P distance with both Gamma and Use ML Distances set; exact distances were not
  affected. A large value of Gamma now gives the same distances as equal rates, as it should
- **Base Freq distance**: the last site of the alignment was left out when computing base frequencies, and a
  sequence without any nucleotide gave undefined values (NaN) in the distance matrix. Such distances are now
  reported and replaced like the undefined distances of the other methods
- **Gene Content distance**: for two genomes whose distance is saturated, for example two genomes that share
  no gene, the distance was set to 1, which is less than the distance between two genomes that share half of
  their genes. Such distances are now treated as undefined and replaced by a value larger than all others
- **Proportion of invariable sites**: with Prop Invariable Sites set, the exact distances of the Jukes-Cantor,
  K2P, F81, F84 and GTR methods gave the number of substitutions per variable site, whereas the
  maximum-likelihood distances of the same methods gave the number of substitutions per site over all sites.
  Both now give the latter, which is the usual convention: rates are scaled so that the mean rate over all
  sites, the invariable ones included, is one
- **F84 distance**: the method failed with the message "Rate matrix and frequencies do not satisfy detailed
  balance condition" whenever the base frequencies of the purines A and G did not add up to ½, because two
  of the four transition rates of the model were set up incorrectly. The Ts/Tv Ratio option, which the method
  uses for maximum-likelihood distances, is now available
- **Nucleotide distances on alignments in which one of the four bases does not occur**: for such alignments
  read from FASTA, phylip, Clustal, MSF or Stockholm files, the Jukes-Cantor, K2P, F81, F84, HKY85 and GTR
  methods failed with an internal error
- **TN93 distance**: for RNA alignments, all distances were reported as undefined, as U was not accepted. A pair
  of sequences in which one of the four bases does not occur had no distance, even two identical sequences;
  the terms of the formula that involve a missing base are now left out
- **Set Base Frequencies = fromChars**: this setting had an effect only in the program window, where it copies
  the frequencies of the current alignment into the Base Frequencies option. A workflow that is run on the
  command line, or run again on other data, used the frequencies stored in the workflow. The frequencies are now
  computed from the alignment at hand whenever the setting is fromChars. If one of the four bases does not
  occur, the method reports this, as the models are not defined for a frequency of zero
- **Saturated or missing distances**: the message that reports the number of such entries counted each pair of
  taxa twice
- **Distances of zero**: some methods reported a distance of -0 between identical sequences
- **Neighbor Net, circular ordering BryantHuson2023**: this ordering, which can be selected in a workflow file
  but is not the default, did not always give an ordering compatible with a circular distance matrix. The pair
  of clusters to join is now selected by the neighbor-joining criterion, and the computation takes cubic rather
  than quartic time
- **Bio NJ**: the method computed the neighbor-joining tree. When two clusters are joined, BioNJ weights their
  distances to the other clusters by a factor that is chosen to minimize the variance of the new distances;
  this factor was always ½, as in neighbor joining, because the sum that determines it was always empty. Bio NJ
  also failed on two taxa
- **Delta Score**: for 340 or more taxa the delta score and the Q-residual score were incorrect, and could be
  negative, because the number of quartets exceeded the range of the integer type used to count them. The scores
  of the individual taxa were affected from about 1300 taxa
- **Min Spanning Network**: the network contained edges that do not lie in any minimum spanning tree. All pairs
  of taxa at a given distance were connected, also pairs that were already connected by a path of shorter
  edges. Now two taxa are connected only if no such path exists, so that with Epsilon set to zero the network is
  the union of all minimum spanning trees. The option Epsilon is unchanged: once the network is connected, all
  further pairs are connected whose distance exceeds the last one used by at most Epsilon. The option
  Min Spanning Tree was not affected
- **PCoA**: the computation took time proportional to the fourth power of the number of taxa, five seconds
  for 300 taxa and sixteen times as long for each doubling; it now takes a fraction of a second for 300 taxa. The method failed when
  all distances are zero. A coordinate for which there is no positive eigenvalue is now zero for all taxa;
  previously the options First Coordinate and Second Coordinate were changed to the last available coordinate,
  so that points that lie on a line were drawn along a diagonal. Eigenvalues that are positive only because of
  rounding error are no longer counted as coordinates
- **Neighbor Joining**: branch lengths were computed in single precision and were accurate to about four
  decimal places for 200 taxa; they are now computed in double precision. The root of the tree is now always
  an inner node; previously it could be a leaf
- **Split Decomposition and Buneman Tree**: a split was discarded if its weight was below a fixed value of
  10⁻⁷ (10⁻⁸ for Buneman Tree), whatever the scale of the distances, so that splits were lost for data with very
  small distances. The value is now relative to the largest distance. Both methods failed on a single taxon,
  and reported an undefined fit when all distances are zero
- **Neighbor Net, distances that are small or large**: a split was discarded if its weight was at most 0.0001
  (0.000001 with the inference algorithm SplitsTree4), whatever the scale of the distances. For distances of the
  order of 0.001, for example between closely related genomes, most splits were lost and the fit was poor. The
  value is now relative to the largest distance, so that multiplying all distances by a constant no longer changes
  which splits are kept
- **Neighbor Net, distances that are not numbers**: if a distance was infinite, the computation did not
  terminate with the inference algorithms ActiveSet (the default) and GradientProjection; if a distance was
  undefined (NaN), a network with a fit of zero was shown without any message. The method now reports the two
  taxa concerned
- **Neighbor Net, inference algorithm ActiveSet (the default)**: the split weights were not those that fit the
  distances best in the least-squares sense, because the computation stopped too early. For the buttercups
  example with Hamming distances (100 taxa), the network lacked 94 of the 223 splits of the best fit and showed 46
  splits that have weight zero in the best fit, and the sum of squared differences between the distances and the
  network was 5 % above its minimum. The fit value did not show this (99.85 against 99.86). The computation now
  continues until the weights are those of the best fit. This takes longer: about 0.1 seconds rather than 0.03 for
  100 taxa, one second rather than 0.2 for 200 taxa and 15 seconds rather than 2 for 400 taxa; for 1000 taxa it takes
  under four minutes, about twice as long as the inference algorithm SplitsTree4. The inference
  algorithm SplitsTree4 is unchanged
- **Neighbor Net, inference algorithms GradientProjection and APGD**: these two choices have been removed. They
  compute the same split weights as ActiveSet, but more slowly, and as they stopped early their results were the
  least accurate of the four; for 400 taxa the fit could be far below that of ActiveSet. A file that names one of
  them is opened with ActiveSet, and a warning is written
- **Options with a value that is not known**: when a file names a value for an option that the program does not
  have, the default is used, as before, and a warning is now written
- **Neighbor Net, inference algorithm SplitsTree4**: a line of debugging output was written for every run
- **Super Network, edge weights**: the choices Mean and Tree Size Weighted Mean were exchanged, and both divided
  by the trees whose taxa a split divides rather than by the trees that contain the split. Mean is now the mean
  length of the split in the trees that contain it, and Tree Size Weighted Mean, the default, the same mean with
  each tree weighted by its number of taxa. For a tree whose root has two children, the split at the root had
  the length of one of the two edges rather than their sum
- **Splits Filter, Maximum Dimension**: the option had no effect. It now removes splits as the Dimension Filter
  does, unless the filter algorithm is Greedy Compatible or the splits are compatible, circular or weakly
  compatible
- **PhyloFusion, mutual refinement of trees**: which unresolved nodes of the input trees were resolved by
  clusters of the other trees depended on the order of the trees, and clusters that fit were left out. Each tree
  now gets all clusters of the other trees that fit into it; of two that do not fit together, the one found in
  more trees is taken
- **Super Network, confidence**: each split now has a confidence value, the percentage of trees that contain
  it among the trees whose taxa it divides
- **Default values of options**: for some methods a new step started with the option values that were last used
  on the computer, rather than with the defaults, so that the same analysis set up on two computers could give
  different results. All options now start with their defaults: Tajima D, Estimate Invariable Sites, Average
  Distances, Upholt and Nei-Li Restriction Distance, Consensus Network, Consensus Outline, Cluster Network,
  Autumn Algorithm and PhyloFusion. The paths and call formats of external programs are still remembered
- **Bootstrap Tree with Transfer Bootstrap**: an edge that separates a pair of taxa from the rest was given
  full support by every replicate, also by those that do not have the pair. Its support is now the usual
  bootstrap support, as it should be for a pair
- **Bootstrap Splits and Bootstrap Tree Splits**: if the computation failed for some of the replicates, these
  were left out without a message and the support values were too low; the bootstrap now reports the failure
- **Bootstrap Tree run from the command line**: the support value of an edge was lost when the edge below it
  was removed for having less than Min Percent support
- **Find**: the text field of the find tool bar now has the keyboard focus when the tool bar opens
- **Warnings**: warnings that arise while a file is read or a method runs are shown as notifications in the
  window concerned, as well as in the message window; the same warning is shown at most once a minute
- **Messages after bootstrapping**: after a bootstrap computation, messages and warnings could stop appearing
  in the message window for the rest of the session
- **Run Workflow**: the traits and the taxon sets of the input file were not passed on, so that a workflow run
  from the command line lacked the traits that the same file has when it is opened in the program
- **Export**: after an export as Nexus with a taxa block, later exports as Nexus contained a taxa block as well
- **Alignment view**: the menu items View > Zoom Out and Zoom Out Horizontal did nothing
- **Menus**: items that cannot do anything in the current tab, such as Edit > Cut for a network, or Copy and
  Find in the workflow tab, are no longer offered. Help > About no longer has the same shortcut as
  Help > Open User Manual
- **Adding a method from a menu**: a method could be added to data that it cannot be applied to, for example
  Bootstrap Tree to a tree that was not computed from characters, or Protein ML Distance to DNA sequences; the
  new step then failed with "Algorithm is not applicable to given input data". Such a method is now not added,
  and a warning says why. In the workflow, alignment and citation tabs the menu items of methods that cannot be
  applied to any data of the document are disabled
- **Select > From Previous Window** in a text tab failed when the text selected before contained characters
  such as brackets
- **Estimate Invariable Sites**: the method reported the proportion of sites that are free to vary as the
  proportion of invariable sites; for identical sequences it reported 0 % rather than 100 %. The same value was
  written into Prop Invariable Sites by Set Site Var Params = fromChars. For 216 or more sequences the estimate
  was based on a single quadruple of sequences, because the number of quadruples exceeded the range of the
  integer type used; for 21 to 215 sequences all quadruples were evaluated, which took minutes for a hundred
  sequences. Quadruples are now sampled until the standard error of the estimate is at most 5 % of its value
- **Tajima's D**: with Exclude Gap Sites set, which is the default, the number of segregating sites was taken
  from the sites without gaps and the nucleotide diversity from all sites, so that D was too large for any
  alignment with gaps or missing states. Without a segregating site, or with fewer than four sequences, the
  report now says that D is not defined, rather than showing NaN
- **Characters Filter**: Exclude Gap Sites had an effect only if Exclude Constant Sites or Exclude Parsimony
  Uninformative Sites was set as well. Sites with three or more states of which at most one occurs in two or
  more sequences were not recognized as parsimony uninformative. A gap or a missing state was counted as a
  state, so that a site that is constant except for a gap was not excluded as constant
- **Median Joining**: in all distances between sequences the first variable site pattern was counted twice,
  so that for some data other median vectors were added than should have been. A median vector was removed when
  it had two links or fewer; for some data the same vectors were then added and removed again without end, and
  the computation did not terminate. A median vector is now removed only when it has fewer than two links, as
  in PopART, and the networks agree with those of PopART on the data sets compared, except that a median vector
  that is left with two links is not drawn as a node: its two edges are shown as one edge with the changes of
  both. The method failed when all sequences are identical
- **Average Distances and Average Consensus**: the distances were half the mean of the distances in the trees,
  as each pair of taxa was counted twice
- **Robinson-Foulds Distances**: the distances were too large by one or more for most pairs of trees
- **Phylogenetic Diversity of trees, unrooted**: the value was the total length of the edges below which some,
  but not all, taxa are selected, rather than the length of the subtree that connects the selected taxa
- **Rooting a tree by midpoint or by outgroup**: when the new root lies on one of the two edges at the previous
  root, that edge lost part of its length. This affected Reroot Or Reorder Trees, Greedy Tree, Consensus Tree
  and the DensiTree view
- **Trees Concordance Filter**: an edge was contracted if the number of trees in conflict with it reached the
  number allowed, rather than exceeded it; with Min Concordance set to 100 all inner edges were contracted,
  also in trees that all agree
- **Unique Topologies with the option Unrooted**: trees were compared by a part of their splits only, so that
  different trees could be reported as one, and the trees returned had no taxa
- **Dimension Filter**: as a step of a workflow, the filter returned no splits when its input was compatible,
  circular or weakly compatible; such splits are now passed on unchanged
- **Removing taxa from splits**: two splits that become the same split were both kept, which gave two bands of
  parallel edges for one split; they are now one split with the sum of the two weights. Confidence values are
  kept
- **Shapley Values**: the values of some taxa could be missing from the report, a different set in each run
- **Rooted Consensus Tree**: the leaves of the tree had no labels
- **Reports**: a percentage of zero by zero was shown as NaN in the reports on phylogenetic diversity and on
  the incompatibility score
- **Citations and tooltips**: the citation shown for PCoA had an incorrect year; the tooltip of Epsilon of
  Min Spanning Network described another method; the report of the delta score named splits as its input; the
  citations shown for the Jukes-Cantor, Nei-Li, Upholt and Gene Sharing
  distances and for the Phi test had an incorrect year or volume; the tooltip of the restriction site length of the Nei-Li and Upholt
  distances now states the default of 1; the tooltip of the Gamma option of Protein ML Distance now states that
  zero, the default, means equal rates

## Changed results

Results obtained with the default options:

- **Protein ML Distance** on alignments read from FASTA, phylip, Clustal, MSF or Stockholm files: all distances
  change. For the first twenty sequences of the buttercups cytochrome C example, written out as FASTA, the mean
  distance changes from 0.139 to 0.124
- **GTR distance**: distances change for all data of unequal base composition. For two sequences with base
  frequencies of 0.1, 0.2, 0.3 and 0.4 that are 0.1 substitutions per site apart, the distance changes from
  0.232 to 0.100
- **Jaccard distance**: all distances greater than zero and less than one become larger; a distance of 0.333
  becomes 0.5
- **Base Freq distance**: all distances can change slightly, as the last site is now counted
- **Gene Content distance**: saturated distances are no longer 1, but a value larger than all other distances
- **TN93 distance**: RNA alignments, and pairs of sequences that lack one of the four bases, now have distances
- **Bio NJ**: trees change, both in topology and in branch lengths. On simulated data with strong noise, the
  topology differed from that of neighbor joining for about two thirds of the data sets
- **Min Spanning Network**: networks have fewer edges; on simulated haplotype data, about half as many
- **Delta Score**: the scores change for 340 or more taxa
- **Neighbor Joining**: branch lengths change from about the fifth significant digit. If two pairs of clusters
  have the same score up to rounding error, another pair may be joined and the topology can change
- **Split Decomposition and Buneman Tree**: splits of very small weight can appear or disappear, when the largest
  distance differs much from one
- **Neighbor Net**: for data whose largest distance is less than one, splits of small weight that were discarded
  are now shown; in a test in which all distances were multiplied by 0.0001, the number of splits rose from 110 to
  1058 and the fit from 50.7 to 99.4. For data whose largest distance is greater than one, splits whose weight is
  at most 0.0001 times that distance are no longer shown
- **Neighbor Net with the inference algorithm ActiveSet (the default)**: networks change for most data, as the
  split weights are now those of the best fit: splits appear, others disappear and weights change. For the
  buttercups example with Hamming distances, the number of non-trivial splits changes from 167 to 223 and the
  largest change of a weight is 1.1, where the largest weight is 21. For distances that fit a tree or a circular
  split network exactly, nothing changes
- **PCoA** for points that lie on a line, or with a coordinate selected that does not exist: see above
- **Estimate Invariable Sites**: the proportion reported is one minus the proportion reported before
- **Bootstrap Tree with Transfer Bootstrap**: the support of pairs of taxa is lower
- **Super Network**: all edge weights change
- **PhyloFusion** on trees that are not fully resolved: networks can change, and no longer depend on the order of
  the trees
- **Splits Filter**: with the default Maximum Dimension of 4, splits are now removed from input that would give
  boxes of dimension five or more
- **Tajima's D**: the value changes for every alignment that has a gap or a missing state
- **Average Distances**: all distances are twice those of earlier versions; the networks of Average Consensus
  have the same splits, with twice the weights
- **Robinson-Foulds Distances**: most distances are smaller
- **Trees rooted by midpoint or outgroup**: an edge at the root can be longer
- **Splits after taxa have been removed**: fewer splits, with the weights added up
- **Median Joining**: networks can change; data for which the computation did not end now give a network

Results obtained with options set:

- **Jukes-Cantor, K2P, F81, F84 and GTR distances with Prop Invariable Sites set**: exact distances are those of
  earlier versions multiplied by one minus the proportion of invariable sites. This includes the K2P distances
  with that option that changed in 6.10.0
- **Protein ML Distance with Gamma set**, and **K2P distance with Gamma and Use ML Distances set**: all distances
  change
- **F81, F84, HKY85 and GTR distances with Set Base Frequencies = fromChars** in a workflow that is run on the
  command line or on other data: the base frequencies are now those of the data
- **Neighbor Net with the circular ordering BryantHuson2023**: the ordering, and with it the network, can change
- **Neighbor Net with the inference algorithm GradientProjection or APGD**: computed with ActiveSet
- **Characters Filter with Exclude Gap Sites, Exclude Constant Sites or Exclude Parsimony Uninformative Sites**:
  more sites are excluded
- **Trees Concordance Filter**: fewer edges are contracted
- **Phylogenetic Diversity of trees with Rooted switched off**, **Unique Topologies with Unrooted**, and
  **Dimension Filter** on circular or compatible splits: see above
